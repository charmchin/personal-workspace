## 原升级阶段的保护措施与授权（历史）

1. 常规升级建议先保存表单并导出独立密码 `.workbench-backup`。本次使用者明确确认旧版全部为可删除的测试数据，因此不再将独立备份作为安装阻塞条件；实际没有清空测试库，也没有收集密码。
2. 退出原应用与全部同数据目录副本，确认没有存活的工作台进程，再复制完整加密数据目录。退出后的原目录副本仍依赖原密钥/口令，不能替代独立密码备份。
3. 保留原 `.app` 并验证归档，校验新包 arm64、版本、应用标识、资源签名、许可文件与隐私扫描。原进程停止后，在应用目录暂存新包，逐次重命名切换并在异常时回滚；不将两个重命名描述为一次原子交换。
4. 禁止在真实数据库上执行故障注入、删除、测试恢复或把数据拷贝到公开仓库。真实备份的完整解密验证需要使用者密码，不从文件存在/扩展名推断已验证可恢复。
