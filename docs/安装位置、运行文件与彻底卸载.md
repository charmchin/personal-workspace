# 个人工作台：安装位置、运行文件与彻底卸载

> 历史记录：个人路径已脱敏为占位符，不能直接执行本文中的旧安装或卸载命令。请使用当前版本的通用说明。

最后核对：2026-08-31  
当前版本：`0.1.1`  
应用标识：`com.local.personalworkbench`  
适用电脑：当前用户 `<local-user>` 的 Apple Silicon Mac

本文列出个人工作台在当前电脑上的实际安装位置、运行所需文件、业务数据、缓存和开发副本，并给出保留数据卸载与不可恢复彻底卸载两套方法。

## 1. 正式安装位置

正式运行的应用位于：

```text
/Applications/个人工作台.app
```

当前大小约为 21 MB。应用包内部只有以下核心内容：

```text
/Applications/个人工作台.app/Contents/Info.plist
/Applications/个人工作台.app/Contents/MacOS/personal-workbench
/Applications/个人工作台.app/Contents/Resources/icon.icns
/Applications/个人工作台.app/Contents/_CodeSignature/CodeResources
```

- `personal-workbench` 是 arm64 主程序，已经包含 React 前端、Rust 后端、SQLCipher 和备份逻辑。
- `Info.plist` 保存应用名称、版本、最低 macOS 版本和应用标识。
- `icon.icns` 是应用图标。
- `_CodeSignature` 是当前本机应用的签名数据。

正式安装版不需要 Node.js、npm、Rust、Cargo、Vite 或源代码目录才能运行。它只调用 macOS 自带的 AppKit、WebKit、Security、Foundation、CoreServices 等系统框架，不安装额外动态库、内核扩展或系统级运行时。

本次实际核对未发现个人工作台专属的 LaunchAgent、LaunchDaemon、特权辅助工具或 macOS 安装收据。`launchctl` 中运行时出现的 `application.com.local.personalworkbench.*` 只是当前 GUI 应用进程，退出应用后即消失，不是后台常驻服务。

## 2. 业务数据和密钥文件

所有工作台业务数据默认保存在：

```text
/path/to/user-home/Library/Application Support/com.local.personalworkbench/
```

当前目录结构如下：

```text
com.local.personalworkbench/
├── workbench.sqlite3
├── workbench.sqlite3-wal
├── workbench.sqlite3-shm
├── database-key.age
└── backups/
    ├── daily-YYYY-MM-DD.sqlite3
    ├── weekly-YYYY-Www.sqlite3
    ├── pre-migration-*.sqlite3
    ├── pre-password-change-*.sqlite3
    └── pre-restore-*.sqlite3
```

各文件作用：

| 文件 | 作用 | 删除后果 |
|---|---|---|
| `workbench.sqlite3` | SQLCipher 加密业务数据库，包含任务、日程、工作、自媒体、成长、投资和设置 | 工作台中的全部业务记录丢失 |
| `workbench.sqlite3-wal` / `-shm` | SQLite 运行期写前日志和共享内存辅助文件，正常锁定/退出时会尝试截断 | 应用运行时单独删除可能破坏未合并写入，不要手工操作 |
| `database-key.age` | 本地口令模式下，使用口令加密包装的随机数据库密钥 | 即使数据库仍在，也无法再用工作台口令解密 |
| `backups/daily-*.sqlite3` | 每日加密快照 | 对应日期的恢复点丢失 |
| `backups/weekly-*.sqlite3` | 每周加密快照 | 对应周的恢复点丢失 |
| `backups/pre-migration-*.sqlite3` | 数据库结构升级前的加密恢复点 | 对应升级前状态无法恢复 |
| `backups/pre-password-change-*.sqlite3` | 修改工作台口令前的恢复点 | 对应操作前状态无法恢复 |
| `backups/pre-restore-*.sqlite3` | 从手动备份恢复前的恢复点 | 对应恢复前状态无法恢复 |

这个目录当前权限为 `0700`，其中数据库、密钥文件和快照权限为 `0600`。

根据安全模式不同，数据库密钥还可能存在于 macOS 钥匙串：

| 钥匙串 service | account | 作用 |
|---|---|---|
| `com.local.personalworkbench` | `database-key` | 钥匙串模式下的随机数据库密钥 |
| `com.local.personalworkbench` | `tushare-token` | 可选 Tushare 行情 Token |

当前电脑使用 `database-key.age` 本地口令模式，核对时没有发现上述两个钥匙串条目；卸载步骤仍会尝试清理它们，以覆盖将来切换模式或配置行情的情况。

## 3. 缓存和偏好设置

当前电脑上还存在以下由 macOS WebKit 和应用生成的辅助文件：

```text
/path/to/user-home/Library/Caches/com.local.personalworkbench/
/path/to/user-home/Library/Preferences/com.local.personalworkbench.plist
/path/to/user-home/Library/WebKit/com.local.personalworkbench/
```

- `Caches` 保存 WebKit 网络缓存、HSTS 和缓存索引，可以安全删除。
- `Preferences` 保存 macOS 应用偏好，可以安全删除。
- `WebKit` 保存本地 WebView 的站点数据、IndexedDB 索引及 WebKit 统计数据库。业务数据不依赖它，但彻底卸载时应删除。

当前未发现以下候选残留：

```text
/path/to/user-home/Library/Saved Application State/com.local.personalworkbench.savedState
/path/to/user-home/Library/HTTPStorages/com.local.personalworkbench
/path/to/user-home/Library/Cookies/com.local.personalworkbench.binarycookies
/path/to/user-home/Library/Logs/com.local.personalworkbench
```

卸载命令仍包含这些精确路径，避免它们以后由不同 macOS 版本创建后被遗漏。

## 4. 开发工程和其他应用副本

开发工程位于：

```text
/path/to/personal-workspace
```

当前大小约 7.6 GB，主要空间来自：

```text
/path/to/personal-workspace/node_modules        约 252 MB
/path/to/personal-workspace/src-tauri/target    约 7.4 GB
/path/to/personal-workspace/dist                约 916 KB
```

这个工程不参与 `/Applications/个人工作台.app` 的日常运行。删除工程不会删除正式应用的业务数据库；反过来，只删除正式应用也不会删除工程和构建产物。

工程内另有一个构建副本：

```text
/path/to/personal-workspace/src-tauri/target/release/bundle/macos/个人工作台.app
```

本次核对时，废纸篓中没有另一份“个人工作台”应用副本。以后更新时若手动保留旧 `.app`，它不是运行依赖，但彻底清理时也需逐个确认删除。Node.js、Rust 和 Cargo 可能被其他项目共用，不属于个人工作台的专属残留，不应为了卸载本应用而删除全局工具链或全局缓存。

## 5. 手动导出的文件

手动加密备份由用户自行选择保存位置，扩展名为：

```text
*.workbench-backup
```

应用不会在数据库中记录所有导出位置，因此彻底卸载前需要单独搜索：

```bash
mdfind 'kMDItemFSName == "*.workbench-backup"c'
```

本次实际核对没有找到手动导出的 `.workbench-backup`；将来是否存在取决于用户选择过的导出位置。

请逐个核对搜索结果后再删除。用户自行导出的 ICS、CSV，以及工作记录中引用的原始素材文件不属于应用文件；工作台只保存它们的路径引用，卸载时不应自动删除这些个人文件。

## 6. 仅卸载应用、保留数据

如果只是暂时不用，或者以后可能重新安装，建议保留业务数据：

1. 退出个人工作台。
2. 删除 `/Applications/个人工作台.app`。
3. 保留 `/path/to/user-home/Library/Application Support/com.local.personalworkbench/` 和可能存在的钥匙串条目。

终端命令：

```bash
osascript -e 'tell application "个人工作台" to quit' 2>/dev/null || true
sleep 2
pkill -x personal-workbench 2>/dev/null || true
rm -rf -- '/Applications/个人工作台.app'
```

再次安装同一应用后，原数据库和口令仍可继续使用。

## 7. 不可恢复的彻底卸载

以下操作会删除正式应用、全部业务数据、快照、密钥包装文件、缓存、偏好、WebKit 数据、钥匙串条目、工程和旧应用副本。执行后如果没有独立的 `.workbench-backup`，数据将无法恢复。

### 7.1 可选：先导出最后一份备份

在应用中进入“设置 → 备份与恢复 → 导出加密备份”，把文件保存到明确位置并记住独立备份密码。确认以后永远不需要数据时，可以跳过此步骤。

### 7.2 退出并确认进程停止

```bash
osascript -e 'tell application "个人工作台" to quit' 2>/dev/null || true
sleep 2
pkill -x personal-workbench 2>/dev/null || true
pgrep -fl personal-workbench || echo '个人工作台进程已停止'
```

### 7.3 注销应用副本并清理钥匙串

```bash
lsregister_tool='/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister'

for app_bundle in \
  '/Applications/个人工作台.app' \
  '/path/to/personal-workspace/src-tauri/target/release/bundle/macos/个人工作台.app'; do
  if [ -e "$app_bundle" ]; then
    "$lsregister_tool" -u "$app_bundle" >/dev/null 2>&1 || true
  fi
done

security delete-generic-password -s 'com.local.personalworkbench' -a 'database-key' 2>/dev/null || true
security delete-generic-password -s 'com.local.personalworkbench' -a 'tushare-token' 2>/dev/null || true
defaults delete 'com.local.personalworkbench' 2>/dev/null || true
```

这些命令不会显示或读取密钥和 Token 内容，只删除与应用标识和账户名精确匹配的条目。

### 7.4 删除所有应用专属文件

先再次核对下面每一个路径，再完整复制执行。不要把路径改成 `/path/to/user-home/Library`、`/path/to/user-home` 或其他上级目录。

```bash
cd '/path/to/user-home'

rm -rf -- \
  '/Applications/个人工作台.app' \
  '/path/to/user-home/Library/Application Support/com.local.personalworkbench' \
  '/path/to/user-home/Library/Caches/com.local.personalworkbench' \
  '/path/to/user-home/Library/Preferences/com.local.personalworkbench.plist' \
  '/path/to/user-home/Library/Saved Application State/com.local.personalworkbench.savedState' \
  '/path/to/user-home/Library/WebKit/com.local.personalworkbench' \
  '/path/to/user-home/Library/HTTPStorages/com.local.personalworkbench' \
  '/path/to/user-home/Library/Cookies/com.local.personalworkbench.binarycookies' \
  '/path/to/user-home/Library/Logs/com.local.personalworkbench' \
  '/path/to/personal-workspace'
```

若未来出现名称不同的旧 `.app` 副本，应先用下面的核对命令找到并逐个确认，不能删除整个废纸篓或整个开发目录的上级目录：

```bash
find '/path/to/user-home/.Trash' '/path/to/user-home/CODE/codex' -maxdepth 6 -name '个人工作台*.app' -print 2>/dev/null
```

Dock 中如果固定了个人工作台图标，请把图标拖出 Dock。不要为了清理单个图标而删除整个 Dock 配置。

### 7.5 核验是否清理完成

```bash
pgrep -fl personal-workbench || echo '进程：无'

find '/Applications' '/path/to/user-home/Library' '/path/to/user-home/CODE/codex' '/path/to/user-home/.Trash' \
  -maxdepth 6 \( -iname '*personalworkbench*' -o -iname '*个人工作台*' \) \
  -print 2>/dev/null

security find-generic-password -s 'com.local.personalworkbench' -a 'database-key' >/dev/null 2>&1 \
  && echo '仍存在 database-key 钥匙串条目' || echo 'database-key 钥匙串条目：无'

security find-generic-password -s 'com.local.personalworkbench' -a 'tushare-token' >/dev/null 2>&1 \
  && echo '仍存在 tushare-token 钥匙串条目' || echo 'tushare-token 钥匙串条目：无'

mdfind 'kMDItemFSName == "*.workbench-backup"c'
```

如果 `find` 没有输出相关路径、钥匙串核验均显示“无”、且不再保留手动备份，即代表应用自有文件已清理完成。

## 8. 关于“完全无痕”的边界

上述步骤可以删除当前电脑上由应用直接拥有或明确创建的文件。macOS 的统一系统日志、LaunchServices 全局数据库、Spotlight 历史索引、APFS 本地快照和 Time Machine 历史备份由系统统一管理，不能安全地只针对一个应用强制抹除；删除全局系统数据库反而可能损坏其他软件环境。

如果曾使用 Time Machine 或其他整机备份，历史备份中可能仍包含加密数据库或应用副本。是否删除这些历史备份应在对应备份工具中单独决定。业务数据库和自动快照本身是 SQLCipher 加密文件，但一旦执行彻底卸载并删除密钥，仍不应把“加密”理解为可以忽略备份介质管理。
