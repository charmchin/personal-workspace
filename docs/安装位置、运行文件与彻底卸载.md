# 个人工作台：安装位置、运行文件与卸载

最后更新：2026-10-03 · 对应源码版本：`0.1.5` · 应用标识：`com.local.personalworkbench`。安装状态以实际应用版本为准。

本说明适用于 macOS 单用户版本。`~` 表示当前用户的主目录；实际源码目录由你克隆或移动工程的位置决定。以下是应用约定的路径和核对方法，不代表已扫描每位使用者的电脑。

## 1. 安装位置与再次运行

建议将构建出的应用放在：

```text
/Applications/个人工作台.app
```

退出后，可在 Finder 的“应用程序”中双击，也可运行：

```bash
open "/Applications/个人工作台.app"
```

如果放在别处，请使用实际应用路径。新源码通过数据目录文件锁排斥第二个合作进程，锁定界面时也不释放；第二次启动尝试聚焦已有窗口后退出。旧安装版没有此协议，仍不要同时启动安装版和工程内的新开发 / 构建副本。

从 0.1.4 起，关闭主窗口或按 `⌘Q` 都会退出应用并释放实例锁；Dock 重新打开已运行的应用会显示/聚焦窗口，不会绕过解锁。关闭前仍需保存表单，未保存输入不保证保留。更早安装版关闭窗口后的行为不同，升级前请明确使用 `⌘Q` 退出。

应用包的主要文件：

| 包内位置（相对于 `.app/Contents/`） | 用途 |
| --- | --- |
| `MacOS/personal-workbench` | arm64 主程序，包含前端资源、Rust 后端及编译链接的本地组件 |
| `Info.plist` | 名称、版本、应用标识与最低系统版本等元数据 |
| `Resources/icon.icns` | 应用图标 |
| `Resources/legal/` | 本项目与第三方许可声明；采用新增许可配置的构建才有此目录 |
| `_CodeSignature/` | 构建 / 签名产生的签名资料；本地临时签名不是 Developer ID 公证 |

构建后的应用无需 Node.js、npm、Rust、Cargo 或工程目录即可运行，但依赖 macOS 自带的 WebKit、Security、AppKit 等系统框架。当前源码没有安装 LaunchAgent、LaunchDaemon、特权辅助工具或后台常驻服务。若使用第三方安装器、包装脚本或自行修改构建方式，请另外检查它们创建的文件。

## 2. 数据保存位置

默认数据目录：

```text
~/Library/Application Support/com.local.personalworkbench/
```

| 文件 / 目录 | 用途与注意事项 |
| --- | --- |
| `workbench.sqlite3` | SQLCipher 加密业务数据库，保存各模块记录与设置 |
| `workbench.sqlite3-wal`、`workbench.sqlite3-shm` | 数据库运行辅助文件；不要在运行时单独删除或只复制主库 |
| `database-key.age` | 本地口令模式下的随机数据库密钥包装文件；删除它可能使数据库无法解锁 |
| `keychain-mode-login` | 特定钥匙串回退模式的标记，按构建及认证模式可能存在 |
| `instance.lock` | 新源码运行期间持有的跨进程文件锁；退出后空文件保留，系统释放锁。不要在运行时删除、移动或替换它；卸载时先退出所有副本，再随整个数据目录移除 |
| `backups/` | 7 个日 / 4 个周 / 3 个最近快照，迁移前、改口令前、恢复前及中断恢复保留文件 |
| 恢复临时文件及其 WAL / SHM | 恢复中断时可能存在；不要把它们视为可随意清除的缓存 |

正常关闭不会删除已保存记录；重新打开同标识的应用并成功解锁后，可继续使用原数据。未保存表单不保证保留。移动工程、删除 `node_modules` 或重新构建应用也不应改变这个数据目录。

0.1.5 升级数据库结构为 2，仅增加日志与任务关联；升级前会生成加密恢复点，原口令不变。旧安装版不能直接打开结构 2。该轮实际安装、原口令解锁和记录保留确认见[0.1.5 验收记录](0.1.5-行动关联与验收.md)。

数据目录应为 `0700`，数据库、密钥包装与快照文件应为 `0600`。目录本身由操作系统路径 API 确定，不以源码目录命名。改动应用标识或运行账户后可能使用不同目录，看起来像“数据不见了”；不要因此删除旧数据。

可能存在的 macOS 钥匙串条目：

| service | account | 用途 |
| --- | --- | --- |
| `com.local.personalworkbench` | `database-key` | 钥匙串认证模式的数据库密钥 |
| `com.local.personalworkbench` | `tushare-token` | 可选行情 Token |

是否存在取决于使用的认证模式和行情配置。不要公开条目内容、工作台口令、独立备份密码或 Token。

## 3. 系统辅助文件

以下为应用标识对应的候选路径；部分路径可能从未创建，存在与否取决于系统版本和运行方式：

```text
~/Library/Caches/com.local.personalworkbench/
~/Library/Preferences/com.local.personalworkbench.plist
~/Library/WebKit/com.local.personalworkbench/
~/Library/Saved Application State/com.local.personalworkbench.savedState/
~/Library/HTTPStorages/com.local.personalworkbench/
~/Library/Cookies/com.local.personalworkbench.binarycookies
~/Library/Logs/com.local.personalworkbench/
```

这些文件不代替业务数据库，但缓存、日志或 WebView 数据也应按私密资料对待。清理前先退出所有应用副本。

早期未打包开发版也可能以 `personal-workbench` 为目录名，在 `~/Library/Caches/` 与 `~/Library/WebKit/` 留下数据；仅检查 bundle identifier 会漏掉它们。另需核对本应用实际使用过的 `.audit` 和隐私构建测试标识，而不是通配删除其他应用目录。系统临时/缓存位置可用 `getconf DARWIN_USER_TEMP_DIR` 和 `getconf DARWIN_USER_CACHE_DIR` 查询，只处理其中已确认属于本应用的子目录。

2026-10-03 已按本机使用者授权执行“保留口令、清空旧数据与旧安装残留”，具体清理范围和验收见[操作记录](旧数据清理与任务删除.md)。这不是完整卸载：当前安装版、原口令包装文件和当前源码有意保留。

## 4. 开发工程和导出文件

在工程目录运行以下只读命令，可确认真实源码位置；不要沿用过去的目录名称：

```bash
git rev-parse --show-toplevel
```

工程内的 `node_modules/`、`dist/`、`src-tauri/target/` 是可再生依赖或构建产物。当前隐私构建入口的应用位于 `src-tauri/target/privacy-build/aarch64-apple-darwin/release/bundle/macos/个人工作台.app`；旧构建也可能仍在 `src-tauri/target/release/bundle/macos/`。旧版应用、ZIP、DMG 可能在构建目录或你自行选择的位置，它们不参与安装版的日常运行。

若曾执行本地升级或验收，工程忽略的 `.local-docs/` 也可能保存旧应用、升级前加密数据副本、截图及操作回执。它们不是运行依赖，彻底卸载时需另行核对；加密副本依然包含历史记录，不应漏掉或当作普通缓存公开上传。先退出所有副本，确认不再需要回退后再移到废纸篓，不要在应用运行时清理它实际正在使用的数据目录。

源码、本地文档、未提交改动可能有保留价值；删除整个工程会一并删除这些内容和本地 Git 历史。Node.js、Rust、Cargo 及全局缓存可能被其他项目共用，不属于本应用专属残留，不建议为卸载本应用而删除。

手动备份为 `.workbench-backup`，保存位置由用户选择；ICS、CSV、素材、笔记原文件也可能在其他目录。应用只保存附件路径引用，不拥有原文件，不应自动删除它们。

可用以下只读 Spotlight 搜索辅助查找备份和应用副本：

```bash
mdfind 'kMDItemFSName == "*.workbench-backup"c'
mdfind 'kMDItemFSName == "个人工作台*.app"c'
```

Spotlight 未索引、外置盘未挂载或文件改名时可能漏报，不能把“无结果”当作不存在。请同时核对已知导出目录、下载目录、外置盘及其他备份介质。

## 5. 仅卸载应用，保留数据

1. 保存表单，使用 `⌘Q` 退出个人工作台；同时关闭开发副本。
2. 在 Finder 中将实际安装的 `.app` 移到废纸篓。
3. 保留数据目录和所需钥匙串条目，不要删除数据库密钥。

重新安装兼容版本、使用同一账户与应用标识后，原记录仍可解锁使用。旧版本不保证兼容新版本数据库；降级前需要单独评估。

## 6. 清除应用自有文件与数据

删除数据库、密钥或备份会造成不可恢复的数据损失。以下步骤只作为操作说明，本项目不会自动执行卸载或清理命令。

### 6.1 先决定是否保留独立备份

如可能再次使用，先在设置页导出加密备份，并确认密码与备份可用。保留备份就不是“删除所有数据”；彻底清除时需单独处理你自行导出的文件。不要只复制正在运行的 SQLite 主库作为备份。

### 6.2 停止所有工作台进程

保存并退出安装版，停止 `npm run tauri dev`，关闭其他构建副本。可在“活动监视器”中确认，或只读检查：

```bash
pgrep -fl personal-workbench
```

有输出时先核对并退出对应进程，不要在数据库仍被使用时清理文件。终端输出可能包含本机路径，提交 Issue 前先脱敏。

### 6.3 核对并移到废纸篓

使用 Finder 的“前往 → 前往文件夹”（`⇧⌘G`），逐项打开第 2、3 节列出的精确路径，核对后把本应用专属目录 / 文件移到废纸篓，并移除实际 `.app`。不要删除 `~/Library`、`Application Support`、`Caches` 或其他共享上级目录。

如果也要清除开发工程，先确认第 4 节得到的实际根目录、未提交改动和本地文件是否均不再需要，再将该工程移到废纸篓。不要删除工程所在的共享父目录。逐个核对旧应用、ZIP、DMG 副本，不要整体清空下载目录或全局开发缓存。

在“钥匙串访问”中按 service 和 account 精确定位第 2 节的两个条目，仅删除确定属于本应用的项目。钥匙串删除不能依赖废纸篓撤销；不要删除整个登录钥匙串或其他软件条目。

应用退出后，可选择通过下列命令清除本应用的系统偏好；这一步会立即删除偏好，不会读出密钥：

```bash
defaults delete com.local.personalworkbench
```

若提示域不存在，表示该偏好域未找到，不应据此执行更大范围的清理。

移除 Dock 中固定的本应用图标即可，不要删除整个 Dock 配置。如存在自行添加的登录项，请在系统设置中只移除本应用项。

### 6.4 复查后处理废纸篓

再次确认进程已停止、第 2、3 节路径已消失、钥匙串对应条目已删除、已知导出目录与外置盘已核对。只在确认不需要恢复后，针对本应用的废纸篓项目执行“立即删除”；不要为此清除其他用户文件。

这些步骤不会修改 GitHub 远端、别的设备、云盘或整机备份；如果你曾同步源码、本地记录或导出备份，需要在对应位置分别核对。

## 7. “完全无痕”的边界

本说明目标是清理可确认属于本应用的文件，不承诺抹除 macOS 统一日志、LaunchServices 全局数据库、Spotlight 索引、APFS 快照、Time Machine 历史或 SSD 物理残留。不要通过删除全局系统数据库来清理一个应用。

整机备份和云盘历史版本中可能仍有旧应用与加密数据；应在相应备份工具中单独决定是否删除。加密不替代密钥、备份介质及历史副本管理，也不能证明数据物理不可恢复。
