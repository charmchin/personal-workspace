本机安装位置、运行依赖、缓存路径和不可恢复的彻底卸载操作，见：[安装位置、运行文件与彻底卸载](安装位置、运行文件与彻底卸载.md)。

## 1. 软件组成

个人工作台是单用户、本地优先的 Tauri 2 桌面应用：

- `src/`：React + TypeScript 界面、页面状态和输入模型。
- `src/styles/`：主题、窗口壳层及各模块布局。
- `src-tauri/src/commands.rs`：前后端命令边界、ICS/CSV 和可选行情。
- `src-tauri/src/repository.rs`：任务、日程、成长、自媒体、工作、投资和复盘逻辑。
- `src-tauri/src/database.rs`：SQLCipher、迁移、密钥、锁定和自动快照。
- `src-tauri/src/backup.rs`：手动加密备份、校验和原子恢复。

应用不启动本地 HTTP 服务，没有云同步、遥测、后台常驻服务或自动更新器。联网行情默认关闭；启用后只允许 Rust 后端访问 `https://api.tushare.pro`。

## 2. 数据、密钥与备份位置

业务数据默认位于：

```text
~/Library/Application Support/com.local.personalworkbench/
```

主要文件：

```text
workbench.sqlite3             SQLCipher 加密业务数据库
database-key.age             本地口令模式下，加密包装后的随机数据库密钥
keychain-mode-login          登录钥匙串回退模式标记（仅部分构建存在）
backups/*.sqlite3            每日、每周及操作前加密恢复点
```

Tushare Token 不在数据库或备份中，而在当前用户的 macOS 钥匙串中。目录权限应为 `0700`，数据库、密钥和快照应为 `0600`。

重要原则：

- 不要单独删除 `database-key.age`、钥匙串中的数据库密钥或 `workbench.sqlite3`。
- 忘记本地工作台口令后，没有后门可以解密原数据库。
- 工作台口令最低 6 个字符；这是便利性下限，仍建议使用更长且混合多种字符的独立口令。
- 手动 `.workbench-backup` 使用独立备份密码；修改工作台口令不会修改旧备份密码。
- 本地快照自动轮换：日快照保留 7 个、周快照保留 4 个，数据库升级前、口令修改前和恢复前的恢复点各保留 5 个。
- “设置 → 备份与恢复”可验证并恢复单个快照，也可逐个删除；恢复前会再创建当前库恢复点，删除则不可撤销。
- 排查前优先在“设置 → 备份与恢复”中导出一份加密备份。

### 恢复过程中退出或被强制终止（0.1.2）

- 新恢复流程先持久化候选库和恢复前副本，再在同一目录原子替换主数据库；正常流程中主路径不会在两次改名之间消失。
- 启动时若发现 `database-before-restore.sqlite3.tmp`、`restore.sqlite3.tmp` 或对应 WAL/SHM，按已有工作台处理，不允许重新初始化或生成新密钥。
- 使用原工作台口令或钥匙串完成解锁后，先验证当前主库；主库有效则继续使用，主库缺失或损坏且恢复前副本有效则安全回滚。仅有未提交候选库时，不自动提升它为主库。
- 遗留候选文件保存在 `backups/interrupted-restore-<UUID>.sqlite3`，界面显示恢复结果提示。如包含 WAL/SHM，整组文件用 `.sqlite3.pending` 及相应日志后缀保留，不作为可直接恢复的单文件快照展示。这些是排查用保留文件，不保证每个候选库都完整有效；不要在核对前删除。它们不自动轮换，以避免尚未排查的文件被清理。
- 如果提示 `RESTORE_RECOVERY_REQUIRED` 或 `UNSAFE_RESTORE_FILE`，不要删除、改名或重新生成密钥；完整保留数据目录、候选文件及日志后排查。旧副本仍带 WAL/SHM 时不自动丢弃日志进行回滚。
- 此修复覆盖进程中断与重启，不构成硬件故障、断电或多个实例并发恢复的完整保障。请避免同时运行开发版和安装版。

### 后端锁定、系统通知与会话边界（0.1.3）

- 后端保存闲置期限，在独立线程每 250ms 检查，并在数据库命令进入和返回时再次核对。5/15/30 分钟或“不按闲置锁定”的设置从数据库加载，修改设置及恢复备份后立即重新应用。
- 页面仅将可见窗口里的真实鼠标、键盘等操作节流为活动通知，最多每秒一次；状态轮询、行情、数据库读取不算用户活动，也没有保活心跳。页面挂起不会阻止后端期限到达；最后一秒内的输入节流可能使期限比最后一次实际输入略早。
- 主线程注册 macOS 锁屏/解锁分布式通知，以及 NSWorkspace 的休眠、唤醒、显示器休眠/唤醒、用户会话离开/返回通知。数据库及备份命令在工作线程执行，避免堵住主事件循环。
- 系统事件先撤销授权，不等待数据库互斥锁；已开始的事务或恢复替换安全收尾后关闭连接并清理运行时密钥。不会粗暴中断 SQLite 写入；这也意味着忙碌操作期间连接和局部密钥副本不保证瞬时销毁。锁定后的新数据库访问被拒绝，锁定前启动的查询结果不得继续返回给页面；后端行情循环在下一次检查点停止，正在进行的 HTTP 请求不保证立刻取消。
- 系统唤醒、解锁 Mac 或返回用户会话不会自动解锁工作台，必须重新认证。认证有会话代号检查；在认证期间发生锁定，旧认证结果不能安装为有效会话。窗口隐藏时页面立即遮蔽内容并请求后端锁定。
- 前端监听锁定事件，卸载业务页面和弹窗、清空口令输入，并以每秒一次状态轮询和窗口恢复时核对作为补充。旧会话响应不能重新显示私密页面。未保存表单会被清除，请在离开或锁屏前保存；已保存数据不因锁定而删除。
- 系统通知不是绝对可靠的安全证明。`com.apple.screenIsLocked` / `com.apple.screenIsUnlocked` 是系统约定名称，不属于公开稳定的锁屏 API；Apple 明确说明分布式通知可能延迟或丢失。因此本版使用公开工作区通知和后端期限作为补充，但不宣称所有 macOS 版本上零延迟、永不漏通知。参见 [Apple 分布式通知说明](https://developer.apple.com/documentation/foundation/distributednotificationcenter)、[会话离开通知](https://developer.apple.com/documentation/appkit/nsworkspace/sessiondidresignactivenotification)。
- 原生验收命令：`cargo test --manifest-path src-tauri/Cargo.toml --test native_lock_smoke`。它在独立主线程进程注册八项实际监听，以应用专用测试名称验证本地和分布式通知回调、访问撤销和移除监听；不会广播真实锁屏/休眠名称，不会操作业务数据。
- 实际 Mac 锁屏、唤醒与重新认证的交互验收仍需用户配合；自动测试不能代替这项验证。应用退出时移除监听并停止监视线程，没有新增后台常驻服务、系统权限或外部请求。
- Mac 已解锁但持续提示 `SYSTEM_SESSION_INACTIVE` 时，可能是会话尚未返回或对应返回通知未送达；退出并重新打开工作台后再认证，不要删除密钥或数据库。

本机 0.1.3 安装位置仍为 `/Applications/个人工作台.app`。升级前的 0.1.1 应用副本保存在源码构建目录 `src-tauri/target/release/bundle/个人工作台-0.1.1-升级前.zip`，仅用于必要时回退应用文件，不含工作台业务数据库；不要在新版运行时回退。未来清理源码及 `src-tauri/target/` 时会一并清理该副本。

## 3. 打开、开发与构建

正式安装后的打开方式：

```bash
open "/Applications/个人工作台.app"
```

开发运行：

```bash
cd "/path/to/personal-workspace"
npm install
npm run tauri dev
```

完整检查：

```bash
npm test -- --run
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo test --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml performance_acceptance -- --ignored --nocapture
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
```

生成本机应用：

```bash
npm run tauri build -- --bundles app
```

构建产物：

```text
src-tauri/target/release/bundle/macos/个人工作台.app
```

这是仅供本机使用的 arm64 构建。正式向其他用户分发前，还需要 Apple Developer ID 签名和公证；本机临时签名不等于公证。

## 4. 推荐的修改与发布流程

1. 先确认问题属于界面、领域逻辑、数据库/安全还是文件导入导出。
2. 修改前确认真实数据已有可恢复备份，不用真实数据库做破坏性测试。
3. 为问题增加可重复测试；涉及数据时使用临时加密数据库。
4. 实现修复并运行前端测试、Rust 测试、格式检查和 Clippy。
5. 用 1360×860 常规窗口与 900×640 最小窗口检查相关页面。
6. 运行大数据性能验收，确认首页聚合小于 300ms、搜索小于 200ms。
7. 重新构建 `.app`，核对 arm64、最低系统版本、签名和默认无外连。
8. 退出旧版本后更新 `/Applications/个人工作台.app`，再做真实启动和锁屏冒烟测试。
9. 若数据库结构变化，必须新增迁移并在升级前生成恢复点，不能直接假设旧库兼容。

- 快照按类型独立轮换；快照恢复完整往返；候选校验失败不替换当前数据库；替换中断则保留遗留文件并在下次解锁时验证处理。
- 独立子进程在四个替换节点直接退出后的重启检查；旧版缺主库状态识别、禁止重新初始化、错误口令/密钥不覆盖文件、损坏候选保留及回滚、符号链接拒绝、带 WAL 副本不静默丢弃日志。
- 快照的列表、恢复和删除均拒绝目录跳转与符号链接，只操作快照目录内的普通 `.sqlite3` 文件。
- 现金资金调整、跨日重复日程、枚举/日期输入、升级前加密快照和前端响应结构校验。
- 数据目录、数据库、密钥和备份的私有权限。
- 10,000 条任务、5,000 条日志、50,000 条价格记录的性能验收。

测试通过只证明已覆盖路径符合预期，不能保证未来环境、第三方行情或所有未知输入永远不出错。遇到异常时应保留原始数据和复现步骤。

## 6. 常见问题排查

### 应用无法打开

1. `uname -m` 应输出 `arm64`。
2. 检查应用：`ls -ld "/Applications/个人工作台.app"`。
3. 检查签名：`codesign --verify --deep --strict "/Applications/个人工作台.app"`。
4. 从终端打开并观察启动错误：

   ```bash
   "/Applications/个人工作台.app/Contents/MacOS/personal-workbench"
   ```

5. 不要为了“重新初始化”而删除数据目录；先确认备份可恢复。

### 口令不正确或无法解锁

1. 区分“工作台口令”“Mac 登录密码”和“手动备份密码”。
2. 记录错误码，例如 `LOCAL_PASSWORD_INCORRECT`、`KEYCHAIN_UNLOCK_FAILED` 或 `DATABASE_UNLOCK_FAILED`。
3. 不要反复替换密钥文件；错误口令不会修改原密钥。
4. 如果仍能进入应用，先导出加密备份再修改口令。

### 关闭后记录看起来丢失

1. 确认打开的是标识 `com.local.personalworkbench` 的同一应用，而不是改过标识的测试构建。
2. 检查数据目录是否仍有 `workbench.sqlite3`，但不要用普通 SQLite 工具改写。
3. 检查是否只是日期范围、项目或状态筛选隐藏了记录。
4. 恢复只通过应用流程操作；密码或完整性检查失败不会覆盖现有数据库。

### CSV 导入失败

1. 从投资页重新导出最新 CSV 模板。
2. 至少保留证券代码、证券名称、交易类型和日期列。
3. 数量、单价、金额、手续费和税费必须是非负十进制，不要加入货币符号。
4. 错误行会单独回滚，不影响合法行；查看导入结果中的首个错误。
5. 卖出或赎回不能超过对应日期之前的持仓。

### ICS 重复或时间不正确

1. 同一文件路径再次导入时，按来源和 UID 更新，而不是新增。
2. 换路径导入会被视为不同来源；需要去重时保持来源路径一致。
3. 无时区时间按 Asia/Shanghai 解释；带 `Z` 的时间按 UTC 转换。

### 行情更新失败

1. 确认“设置 → 可选联网行情”已启用且 Token 已配置。
2. 无 Token、权限不足或网络失败都不影响手工价格和其他模块。
3. 应用保留最近一次有效价格；基金净值不可用时使用手工录入。
4. 不要把 Token 写进问题截图、日志或代码。

### 页面错位或显示拥挤

1. 将窗口恢复到至少 900×640。
2. 分别检查浅色、深色和跟随系统模式。
3. 检查 macOS 的“减少动态效果”和显示缩放设置。
4. 提供页面名称、窗口尺寸、主题和截图，不要包含持仓金额或 Token。
