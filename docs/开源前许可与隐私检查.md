- 读取本地全部可达 refs 的 3 个提交，以及 129 个去重文件对象：84 个文本对象、45 个二进制对象。未拉取 GitHub 的隐藏 refs，不覆盖其他克隆、fork、远端缓存或已删除的外部发布物。
- 文本规则包括作者主目录路径、私钥 PEM 标识、常见 GitHub / AWS / OpenAI 凭据格式、凭据赋值、长字符串、邮箱及手机号候选。命中项逐一核对，输出仅包含类别、相对文件名和行号，不保存原始凭据值。
- 历史二进制对象均为应用图标，补充检查了可打印字符串；没有执行图像 OCR 或隐藏数据取证。这不是对任意二进制隐私的完整证明。
- 另用只读字符串检查查看现有本机 release 主程序，不启动应用，也不接触真实业务数据库。
- 依据本项目 LICENSE、锁文件、517 项依赖的声明快照、原文及补充来源核对许可。仅为许可核对访问公开上游元数据，没有提交 Issue 或联系维护者。

这是一轮有明确范围的模式扫描和人工复核，不是 Gitleaks / TruffleHog 全规则认证，也不能证明不存在未知格式的凭据或任意敏感内容。

初次检查发现，三个可达提交的作者 / 提交者邮箱包含个人联系信息，历史文本保留旧本机路径。现已在隔离副本中将作者和提交者邮箱替换为用户从 GitHub 设置提供的 `noreply` 邮箱，脱敏三个历史文档中的用户名及个人路径。本报告不复述原邮箱、旧提交标识或个人主目录。

逐提交核对确认业务代码、图标、文件模式、提交日期、消息与父子顺序不变；隔离仓库全部数据对象复查与 Git 完整性检查通过。经再次授权，仅以绑定准确旧 SHA 的 `--force-with-lease` 更新远端 `main`，未进行镜像强推或删除其他 refs。新的历史端点为 `3dc584d`。

本地 `main` 与 `origin/main` 已对齐脱敏历史；先确认不存在已暂存改动，再只调整分支与索引基线，不覆盖工作文件。接续前后 123 个工作文件校验值一致，随后仅补充本报告的处理进度。操作时曾将原历史 bundle、工作文件备份与提交映射保存在私有目录，并增加本地 Git exclude 规则防止意外提交。后续按使用者清除旧版及备份的授权，已删除这些隔离副本和归档；当前工程、未提交文件与 `.git` 未删除或改写，不能宣称整台电脑已无旧个人信息。见[后续清理记录](旧数据清理与任务删除.md)。

### 2. 构建包的编译路径：新本机构建已修复（2026-10-03）

现有工程构建的 release 主程序中，发现 673 行可打印字符串包含作者主目录路径：669 行关联 Cargo 注册表依赖，4 行关联工程目录。这是编译位置泄露，不是持仓、笔记或数据库密钥泄露；行数不等于唯一文件数。

该问题不阻止本机运行，但源码文本脱敏不能消除已经编译进安装包的字符串。现已新增 `npm run app:build`：以动态目录映射保护 Rust 和原生 C / C++ 编译路径，在独立缓存中打包并逐文件扫描实际产物，未在旧二进制上替换字符串。直接 Tauri 构建缺少映射时由预检拒绝；开发运行方式不变。

第一轮重建仍检出 OpenSSL 的 CFLAGS 诊断字符串与动态加载目录。进一步在隔离构建阶段脱敏生成诊断，并将静态 `no-module` 构建的两个加载目录改为虚拟路径；没有修改共享依赖源码、加密算法、真实静态库安装前缀或许可原文。详见[构建隐私与产物检查](构建隐私与产物检查.md)。

新包先扫描，再以无需证书的本地 ad-hoc 签名封装资源、核对完整性并重扫。该签名不是 Developer ID 签名或 Apple 公证。包内四项许可资源与工程原文逐字节一致。

隔离启动另用临时应用标识构建测试副本，在系统沙箱下禁止联网、访问真实业务目录及钥匙串文件 / securityd 服务；确认进程存活并创建原生主窗口，未设置口令、创建数据库或解锁。测试进程已停止，空测试数据目录已删除；测试包及专属缓存资料转移到忽略的私有验收目录。随后重新构建正常应用标识的产物，不将测试标识用于正式包。
