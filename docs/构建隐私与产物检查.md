# 构建隐私与产物检查

2026-10-03 · Apple Silicon macOS · 当前源码版本 0.1.4；下列 0.1.3 校验值保留为历史。

## 标准构建

```bash
npm run app:build
```

依赖已在本机缓存时，可要求 Cargo 不联网、不改锁文件：

```bash
npm run app:build -- -- --locked --offline
```

第二组 `--` 将后续参数交给 Cargo，而不是 Tauri。第一次准备依赖仍可能需要联网；业务离线与依赖安装离线不是同一承诺。

产物：

```text
src-tauri/target/privacy-build/aarch64-apple-darwin/release/bundle/macos/个人工作台.app
```

默认只覆盖 arm64、release、`.app`，不支持借此命令跳过打包、构建 debug、切换目标或宣称 DMG / ZIP 已扫描。脚本仅使用无需证书的本地 ad-hoc 签名封装资源并核对完整性，不自动安装、上传、公证或更换真实数据目录。它不是使用 Apple Developer 身份的正式分发流程。旧 `target/release/` 的产物被保留，不随新构建自动脱敏。

## 参数与预检

- 动态识别工程根目录、用户主目录、Cargo / Rustup 目录、临时目录及存在的真实路径别名，映射到 `/workbench-build/` 下的虚拟编译目录，不硬编码作者用户名。
- Rust 使用 `--remap-path-prefix`，更具体的目录映射排在后面；原生 C / C++ 使用 `-ffile-prefix-map`，同时启用 cc-rs 的 shell-escaped 参数解析，处理含空格的目录。
- 仅修改构建子进程的环境，不改变 `HOME`、全局 Cargo 配置、业务数据与文件引用路径、正常构建的应用标识、数据库密钥或口令；优化和金融计算参数不变。OpenSSL 的不可用动态模块目录例外，见下文。
- 已显式提供的 `CARGO_ENCODED_RUSTFLAGS` 或 `RUSTFLAGS` 保留，再追加映射。该入口使用 Cargo 高优先级的环境 flags；Cargo 配置文件中的 flags 不会自动合并。如有自定义配置，应把必要 flags 显式提供为环境参数并验证，不要假设其仍自动生效。另有 target-specific Rust flags 的自定义环境需要先整合，不应静默依赖它们。
- 控制字符、`=`、`$` 或反引号目录名不在当前入口的支持范围，预检会拒绝；普通中文和空格可用。
- Tauri 的 `beforeBuildCommand` 检查实际 Rust 与原生映射参数；缺少映射的直接 `tauri build` 提示使用标准入口。它不是对拥有源码修改权限的人的安全沙箱，绕过入口、另换配置或只用 Cargo 编译的产物不能视为已验收。

参考：[Rust 路径重映射](https://doc.rust-lang.org/rustc/remap-source-paths.html)、[Cargo flags 优先级](https://doc.rust-lang.org/cargo/reference/config.html#buildrustflags)、[Clang 编译参数](https://clang.llvm.org/docs/ClangCommandLineReference.html#cmdoption-clang-ffile-prefix-map)。链接器或外部生成器可能单独写入路径，因此不能只依据参数存在判定安全，必须扫描实际产物。

## OpenSSL 生成元数据

当前锁定的 vendored OpenSSL 会把 CFLAGS 存为诊断字符串，同时把安装阶段的绝对目录编入 `ENGINESDIR` / `MODULESDIR`。即使文件宏已重映射，诊断中的映射参数本身仍包含本机路径。

标准入口为 OpenSSL 提供项目内 Perl 包装器；普通 Perl 调用仍交给原运行时。仅在隔离构建目录内：

- 向 `mkbuildinf.pl` 传递经过路径脱敏的**诊断参数副本**，不修改真实 C / C++ 编译参数。
- 在 `Configure` 完成后，把生成 Makefile 的两项动态加载目录改为 `/workbench-build/openssl/engines` 与 `/workbench-build/openssl/modules`。真实安装前缀、头文件、静态库输出和 OpenSSL 配置目录不变。
- 要求当前 vendored 构建包含 `no-module`；目录越界、字段缺失或重复时失败，而不是猜测新上游的生成格式。

这些虚拟目录不应实际创建；本应用依赖静态 OpenSSL 的 SQLCipher，不使用外部动态模块。没有修改共享 Cargo 缓存的上游源码、加密算法或许可原文。诊断 CFLAGS 经过脱敏后不再是原始本机命令的逐字副本。将来升级 OpenSSL 或启用外部模块时必须重新核对此处理，并重跑加密与恢复测试。

## 扫描与失败处理

打包成功后入口自动遍历输出目录的 `.app`，先检查文件和路径，再执行本地 ad-hoc 签名及 `codesign --verify --deep --strict`，最后重扫包含资源封印的最终包。读取所有普通文件，包括主程序、Info.plist、图标、许可和签名资料。按已识别的本机目录前缀检查 UTF-8 / UTF-16LE 字节，流式扫描保留交界数据，不能漏掉跨读取块的路径。除标准签名操作外，不做二进制字符串替换，也不修改许可原文。

独立扫描：

```bash
npm run app:privacy -- "src-tauri/target/privacy-build/aarch64-apple-darwin/release/bundle/macos/个人工作台.app"
```

输出只包含相对于应用包的文件名、扫描文件数、字节数和问题类别，不输出匹配的个人目录值。发现路径、符号链接、特殊文件、缺失可执行文件或扫描错误时返回非零状态，不把失败产物当作可分发构建。

当前规则针对本机构建路径，不是全格式凭据扫描、版权审查或通用隐私认证。压缩容器、未知生成器、来自其他电脑的旧缓存及未列入的自定义外部构建根需要额外核对。扫描失败时应定位构建来源或参数，再重建；不要删除许可声明或在签名后的二进制上直接替换字符串。
